# お笑い相談所 
>まだ知らない「面白い」に出会う

## 1. サービス概要

「お笑い相談所」は、今まで知らなかった芸人や、名前は知っていてもネタを見たことがない芸人との出会いを通じて、新しい「面白い」を発見できるアプリです。ユーザーが選択した条件に応じたAIによる芸人推薦と、他のユーザーによる芸人のおすすめ投稿の２つの方法で、新しい「面白い」を知るきっかけを提供します。

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験

幼少期からお笑いが好きで、漫才やコント、トークバラエティ番組など、さまざまな形でお笑いに触れてきました。

しかし、最近はお笑いを見る際に、すでに面白いと知っている芸人や、過去に見たことのあるネタを検索することが多く、視聴する芸人やネタが固定化していると感じていました。

新しい芸人やネタを自分から探そうとしても、「どう検索すれば自分好みのお笑いが見つかるのか」「その芸人やネタは自分にとって面白いのか」といった疑問があり、探すために時間を使うことをためらってしまうこともありました。

そこで、条件を選ぶだけでおすすめの芸人を知ることができ、他のユーザーのおすすめ投稿からも芸人の魅力を知ることができるアプリがあれば、新しいお笑いに触れるきっかけを増やせるのではないかと考えました。


### 2-2. なぜそれが「気になった」のか

幼少期からさまざまなお笑いに触れる中で、芸人のネタやトークには人を笑顔にする力があると感じてきました。

また、友人や家族とお笑いについて話す際に、「その芸人は知らなかった」「おすすめされたネタを見たら面白かった」といった反応をもらうことがありました。

自分がおすすめした芸人をきっかけに、誰かが新しい「面白い」に出会えたことが嬉しく、こうした体験をもっと多くの人に届けたいと考えるようになりました。

この経験から、「まだ知らない『面白い』に出会う」をテーマに、本アプリを開発しようと考えました。

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

新しい芸人やネタに興味があっても、普段視聴している芸人やネタに偏ってしまい、まだ知らないお笑いに出会う機会が少ないことです。
---

### 3-2. 本当に解決したい課題は何か

本当に解決したい課題は何かを深掘りした結果、以下のような思考で本当に解決したい課題に辿り着きました。

### なぜ①：新しい芸人に出会う機会が少ないのか？

普段から知っている芸人や、面白いと分かっているネタを優先して視聴することが多いためです。

### なぜ②：知っている芸人やネタを優先するのか？

新しい芸人を探す方法が分からず、見つけた芸人が自分にとって面白いかどうかも判断しにくいためです。

### なぜ③：面白いか分からないことが、なぜ障壁になるのか？

限られた時間の中で、楽しめるか分からない動画を探したり視聴したりすることに心理的な負担を感じるためです。

### 本当に解決したい課題

新しいお笑いに興味があっても、探し方が分からないことや、自分に合うか判断しにくいことが障壁となり、新しい芸人やネタに触れる行動につながりにくいことです。

## 4. 想定ユーザーについて


### 4-1. 想定しているユーザー

平日仕事で忙しく、日常生活の中で自由に使える時間が限られている人を中心に想定しています。

年齢設定
  - 年齢：20代〜30代前半
  - 理由：仕事や日常生活のさまざまな用事によって、自由に使える時間が限られている社会人を想定しているためです。その限られた時間の中でもお笑いを楽しんでいる人に対して、AIによる芸人推薦や他のユーザーのおすすめ投稿を通じて、新しい芸人やネタを探す負担を減らし、新しい「面白い」に出会うきっかけを提供したいと考えています。ただし、今回解決したい課題は年齢によって生じるものではないため、この年齢設定は現時点での仮説であり、利用者を年齢で制限するものではありません。

生活・状況設定：
  - 生活・状況：平日は仕事が忙しく、限られた自由時間にお笑いを楽しんでいる。
  - 理由：帰宅後などの自由時間にyoutubeなどでお笑いを見ることはあるものの、すでに知っている芸人や過去に見たネタなどを選んでしまい、新しい芸人やネタを探すことに時間を使えていない人を想定しています。アプリを使うことで短時間で自分の気分に応じて新しい芸人に出会うきっかけを提供できます。

環境設定：
  - 環境：仕事終わりにyoutubeなどでお笑いを楽しみたい時にスマートフォンから利用することを想定しています。
  - 理由：お笑いを見る際に今まで見たことのある、またはすでに知っているお笑いだけだと飽きがきてしまうことが想定され、新しい芸人やネタを探そうとしても、どう調べれば良いのか、またその芸人・やネタはユーザーにとって面白いと感じるのかなどの懸念点から新しく探すことへの心理的負担がかかることが想定できます。今回のアプリを使うことで新たなお笑いに出会うきっかけを作ることができます。また、今の気分に合わせていくつか項目を選ぶだけなので、アプリ使用の心理的負担を抑えています。

### 4-2. 自分とユーザーの距離

- 現在の私自身が想定ユーザーと最も近いと考えています。 

- 理由:自分自身が、いつも同じ芸人やネタを視聴してしまい、新しいお笑いを探すことに難しさを感じていたためです。実際に経験した課題を出発点にすることで、利用者の行動や心理的なハードルを具体的に考えながら開発できると考えています。

## 4-4. ユーザーがサービスを導入して利用するまでのイメージ(導入・継続の流れ)

以下の内容を仮説としてサービス導入と利用するまでのイメージとします。

### 初回利用

1. 新しいお笑いを探したいと思い、アプリにアクセスする

2. トップページで「AI推薦」または「みんなのおすすめ」を選択する

3. AI推薦では条件を選択し、おすすめされた芸人と動画を確認する

4. みんなのおすすめでは、他のユーザーが紹介する芸人やおすすめ理由を閲覧する

5. 自分もおすすめを投稿したくなった場合に、ユーザー登録・ログインを行う

### 継続利用のきっかけ
以下の理由が想定される

1. その日の気分に合わせて違う芸人を探したいとき

2. 他のユーザーの新しいおすすめ投稿を見たいとき

3. 自分が新しく見つけた芸人を他の人に紹介したいとき

そのため、芸人名を知らなくても、そのとき見たいお笑いの条件から探し始められる仕組みがほしいと考えました。

また、友人や家族からおすすめされた芸人を見て面白いと感じた経験から、他のユーザーのおすすめ理由を参考にできる仕組みにも価値があると考えています。


### 5-3. 差別化を「体験価値」で表現する

## 7. このアプリで実現すること

### MVPで作る機能
1. AIによる芸人推薦機能
・ユーザーが見たいお笑いの条件を選択する（項目を複数選択）
・AIがおすすめの芸人を3組紹介する
・AIに推薦された芸人ごとにおすすめ理由を表示する
・YouTube動画を取得・表示する
・AI推薦の利用にログインは不要とする

2. みんなのおすすめ

・おすすめ投稿のある芸人を一覧表示する
・芸人ごとに複数ユーザーのおすすめ投稿をまとめ
・芸人詳細画面で、それぞれのおすすめ理由を閲覧できる
・ログインしたユーザーがおすすめ投稿できる
・1人のユーザーが同じ芸人に投稿できるのは1件までとする
・自分の投稿を編集できる
・芸人名の入力時に登録済みの候補を表示する
・未登録の芸人は、投稿確定時に新しく登録する
・芸人名の前後の空白除去や同一名称チェックによって基本的な重複登録を防ぐ

3. ユーザー認証
・メールアドレスとパスワードによるユーザー登録・ログイン
・AI推薦とおすすめ投稿の閲覧はログイン不要
・おすすめ投稿の作成・編集にはログインが必要
・他のユーザーの投稿は編集できない

4. データ管理
・ユーザー情報、おすすめ投稿、投稿対象の芸人情報をDBで管理する
・同じ芸人への複数ユーザーからの投稿を許可する
・AI推薦された芸人は、推薦時点ではDBに保存しない
・「みんなのおすすめ」で投稿された芸人のみを芸人一覧に表示する

### 本リリースで作る機能
・気になった芸人のお気に入り登録
・お気に入り一覧
・AI推薦履歴の保存
・Googleアカウントによるログイン
・芸人名の表記揺れへの対応
・AI推薦の精度改善
・投稿の検索・絞り込み機能


## 8. このアプリの懸念点とその対策

### 懸念点① AIが実在しない芸人や誤った情報を含む推薦結果を返す可能性がある。

- 対策
AIの出力形式を定める
YouTube動画の検索結果との整合性を確認する仕組みを検討する
AI推薦結果を自動的に芸人DBへ保存しない
実際の推薦結果を検証しながらプロンプトを改善する

## 9. 今後の展開・発展の方向性

本アプリは、AIによる芸人推薦とユーザーによるおすすめ投稿を通じて、新しい「面白い」に出会うきっかけを提供するサービスです。

MVPでは「新しい芸人を発見すること」を中心に実装しますが、将来的には、発見した芸人を記録したり、他のユーザーとおすすめを共有したりすることで、継続的に新しいお笑いに出会えるサービスへ発展させたいと考えています。

### 今考えている発展案

- 追加機能の方向性

1. お気に入り登録機能

AI推薦や他のユーザーの投稿を通じて発見した芸人を、お気に入りとして保存できる機能を追加します。

気になった芸人を後から見返せるようにすることで、一度の利用で終わらず、継続的にアプリを利用するきっかけを作ります。

2. AI推薦履歴の保存

過去にAIから推薦された芸人を確認できる機能を追加します。

以前紹介された芸人を再度探す手間を減らし、気になった芸人の動画を後から視聴できるようにします。

3. 芸人の検索・絞り込み機能の充実

芸人名だけでなく、ジャンルや芸風などの条件から芸人を探せる機能を検討します。

おすすめ投稿が増えた際にも、自分の好みに合った芸人を見つけやすくすることを目指します。

4. 蓄積された投稿データの活用

ユーザーのおすすめ投稿が増えることで、同じ芸人に対するさまざまな評価やおすすめ理由が蓄積されます。

将来的には、投稿内容をもとに芸人の特徴や魅力を整理し、ユーザーが芸人を探す際の参考情報として活用することを検討します。

なお、投稿内容のAI推薦への活用については、データの品質や推薦精度を検証した上で判断します。

- UI・体験の改善

1. スマートフォンでの操作性向上

想定ユーザーは、仕事などによって自由時間が限られており、帰宅後や休憩時間にスマートフォンから利用することを想定しています。

そのため、条件選択から推薦結果の表示、動画視聴までを少ない操作で進められるUIを目指します。

2. AI推薦結果の分かりやすさの改善

推薦された芸人について、なぜおすすめされたのかを簡潔に表示し、動画を視聴する前に興味を持てるようにします。

将来的には、推薦結果に対するユーザーの反応を参考に、条件の選びやすさや推薦理由の表示方法を改善していきます。

3. おすすめ投稿の閲覧・投稿体験の改善

投稿が増えても目的の芸人を探しやすい一覧画面や、入力負担の少ない投稿フォームを検討します。

- 機能以外の工夫

1. ユーザーからのフィードバック収集

実際の利用者にヒアリングを行い、芸人を探しやすかったか、推薦結果に興味を持てたかなどを確認します。

開発者の想定だけで機能を追加するのではなく、利用者の意見をもとに改善の優先順位を判断します。

2. 投稿情報の品質維持

おすすめ投稿が蓄積されることで、誤った情報や不適切な内容が投稿される可能性もあります。

将来的には、通報機能や投稿内容の管理方法を検討し、安心しておすすめを閲覧できる環境を整えます。

3. 継続的な運用と改善

外部APIの利用料金や制限、アプリの動作状況を確認し、継続してサービスを提供できる仕組みを整えます。

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- フレームワーク：Ruby on Rails 8.1系
- DB：PostgreSQL
- デプロイ先：Render
- 使用予定ライブラリ：Devise / Hotwire（Turbo・Stimulus）/ Bootstrap
- 外部API：youtube Data API / Open AI API（候補）

※「候補」としている技術については、実装時に必要性や導入コストを確認して決定します。

---

### 10-2. 技術選定の比較検討

（例）
| 候補 | 採用/不採用 | 理由 |
| Ruby on Rails 8.1系 | 採用 | これまで学習してきたRailsの知識を活かせることに加え、フロントエンドとバックエンドを一つのフレームワークで開発できるため。 |

| React・typescript | 不採用 | 今今回実装したい画面や動的なUIは、RailsのERBやHotwireで実現できると考えたため。また、フロントエンドとバックエンドを分離する構成に比べて、新たな学習や実装の負担を抑えられると判断しました。 |

| PostgreSQL | 採用 | Railsでの利用経験があり、ユーザー・芸人・おすすめ投稿の関連データを管理するため。 |

| Render | 採用予定 | RailsアプリケーションとPostgreSQLを利用したデプロイ先として選定しました。料金や利用制限、本番環境の構築方法を確認した上で利用する予定です。 |

| Devise | 採用 | ユーザー登録・ログインなどの認証機能を実装するため。Rails標準の認証機能と比較し、必要性を判断します。 |

| Hotwire（Turbo・Stimulus） | 採用 | Railsを中心とした構成のまま、画面の部分更新や芸人名の入力補完など、動的なUIを実現できるため。 |

| Bootstrap | 採用 | スマートフォンに対応した画面を効率的に実装するため。|

| YouTube Data API | 採用 | AIが推薦した芸人の関連動画を取得し、ユーザーがすぐにネタを視聴できる体験を提供するため。|

| OpenAI API | 採用候補 | ユーザーが選択した条件に応じて芸人を推薦する機能を実装するため。推薦結果の精度、料金、レスポンス速度などを検証して採用を判断する。|

- 今回チャレンジしたい点

1. 外部APIを組み合わせた機能の実装

LLM APIを利用してユーザーの条件に合った芸人を推薦し、YouTube Data APIから関連動画を取得する機能に取り組みます。

外部APIから取得した情報をそのまま信用するのではなく、レスポンスの検証やエラー処理を行い、想定外のデータが返ってきた場合にも適切に対応できる実装を目指します。

2. データベース設計と認可処理

ユーザー、芸人、おすすめ投稿の関連を整理し、複数ユーザーが同じ芸人をおすすめできる仕組みを実装します。

また、同じユーザーによる同一芸人への重複投稿を防ぎ、投稿者本人のみが編集できるようにすることで、データの整合性とセキュリティを意識した設計に取り組みます。

- 不安な点

1. Open AI APIによる推薦結果の正確性

AIが実在しない芸人を推薦したり、ユーザーの条件と合わない結果を返したりする可能性があります。

そのため、推薦結果の形式を検証し、必要に応じて再取得やエラー表示を行う仕組みを検討します。

2. YouTube Data APIによる動画取得

推薦された芸人と関係のない動画が検索結果に含まれる可能性があります。

また、APIの利用制限や費用も考慮する必要があります。

開発初期に小規模な技術検証を行い、取得結果の精度と利用条件を確認します。

### 10-3.キャッチアップ不足の懸念

キャッチアップ不足の段階では以下の懸念点があります。
1. 完成までのハードルが高い
外部APIの連携など新しい技術にチャレンジする、またAIによる芸人推薦機能の出力内容に「存在しない芸人」「無関係なYoutube動画」が含まれないかのチェック・改善に時間を要することが懸念されます。
